# 架构取自 ZCode 的分层,里程碑取自 17 章的顺序

我们的目录分层来自 ZCode —— `provider` / `server` / `client`,每个包是一层 —— 因为它回答了产品规模下**代码放哪**。我们的构建顺序来自 learn-claude-code 的 `s01`–`s17`,因为它按依赖顺序回答了**下一个做什么**。两个参考的读法不同:ZCode 是结构参考,learn-claude-code 是顺序参考,都不整体照搬。

## 考虑过的方案

**把 17 章照搬成目录。** 否决:每一章都是刻意自包含的重写,不是一层。`s01_agent_loop/code.py` 只有 151 行;`s08` 和 `s15` 各自从零重建了整个循环。按那个结构建的目录会容纳十七份近似重复的实现,而不是一个产品。

**复制 ZCode 的完整 pnpm monorepo。** 否决:它在前期就摊开 workspace 配置和跨 13 个包的硬边界。那份成本由持续交付的团队摊销,而不是由一个人用 1–3 个月摊销。

## 后果

- 一个目录存在的理由来自 ZCode 的分层,**永远不是**"因为 sNN 那一章这么说"。
- 章节号出现在里程碑和提交历史里,不出现在 import 路径里。
- 可以按 Apache-2.0 直接借鉴 ZCode 的源码;保留其 `NOTICE` 与逐文件署名。
