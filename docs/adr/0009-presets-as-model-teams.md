# 0009 preset:角色文件写用途,配置文件写这一次跑用谁

状态:接受(v2-12)

## 背景

角色文件里已经能写死模型(`model: deepseek:deepseek-v4.1`)。但"哪家便宜"这件事会变:
换了套餐、换了网关、试了另一家、白天用贵的晚上用便宜的。写死在角色文件里的话,换一次
就要把每个角色的文件改一遍,而且改完还得记住自己改过哪些 —— 最容易漏掉的那个角色,
往往是跑得最久的那个。

## 决定

**一、两层名字:槽位是用途,preset 是这次跑用谁。**

角色文件写 `model: preset:scout` —— 它说的是"我要扮演 scout 这个用途",不提具体哪家。
`presets` 在 `settings.json` 里定义槽位:

```json
{
  "presets": {
    "cheap": { "scout": "glm:glm-4.5-air", "review": "glm" },
    "strong": { "extends": "cheap", "review": "deepseek:deepseek-v4.1" }
  },
  "preset": "cheap"
}
```

于是"整队换模型" = 改 `preset` 那一行(或这一次跑 `HCODE_PRESET=strong hcode`),
角色文件一个字不动。

**考虑过的另一种做法**:preset 直接按**角色名**覆盖,`{"cheap": {"explorer": "glm:..."}}`
—— 好处是角色文件完全不用改。没采用,理由是它把 preset 绑死在"叫这个名字的角色"上:

- 项目里自定义的角色(我叫它 `scout` 而不是 `explorer`)不在 preset 里,换队时被静默
  漏掉,而用户会以为整队都换了。
- 同一个角色在不同项目里想用不同档,表达不了(名字只有一份)。
- 槽位让"用途"变成一根可复用的轴:两个角色可以是同一个槽位,一个角色换槽位就换了档。

代价如实说:每个角色文件要写清自己是什么用途,多一行。这一行的价值是它把"角色干什么"
写下来了 —— 那本来就是角色文件该回答的问题。

**二、解析在启动时做完,派发路径上不知道 preset 存在过。**

`applyPresets` 把每个角色的 `model` 从 `preset:scout` 换成这一队里的具体值,之后
`AgentDef` 里再也没有槽位引用。好处是 v2-11 的"续跑按同一角色重新装配"自动跟着当前队伍
走:换了队重开,追问也会用新队 —— 不需要在派发路径上多带一个"这次跑用哪队"的状态。

**三、接不上就回退主对话并说一声,不拦下会话。**

槽位不在这一队里、压根没选 preset、队名写错、`extends` 断了或绕成环 —— 一律
**启动时 stderr 说一句 + 该角色用主对话的模型**,会话照常能起。回退是定义好的行为,
不是失败;拦下来只会让人连活都干不了。

唯一**直接报错**的是 `presets` 结构本身写坏(槽位值不是字符串之类):那种情况下必须让
hcode 起不来。降级成"没有 presets"的话,用户会以为队伍生效了,而其实每个角色都在用
主对话的模型 —— 还查不出为什么。

**四、`model` 里的 `preset:` 前缀是必须的,槽位不许指向另一个 preset。**

没前缀就与 provider 名字分不开(有人真会叫一家 provider `preset`)。槽位指向另一个
preset 会让解析变成猜谜(算哪一队的?按谁选的?),要改队伍就改 `extends`。

**五、项目级与用户级的**同名队整队覆盖**,不逐槽位合并。**

槽位是照着 `extends` 的意义写的,把两层的槽位混起来,继承链会指向一个原作者没想过的
组合。整队替换的含义是"这个项目对 `cheap` 的理解就是这一份"。

## 后果

- `model` 的取值域变成三种:`provider`、`provider:模型`、`preset:槽位名`。三种都由
  `parseModelBinding` / `parseSlotRef` 分开解析,互不误伤(`preset:scout:cheap` 这种
  槽位名里带冒号的写法按整段算槽位名)。
- **顺手修掉 v2-03 的一个漏**:`providerFor` 此前只收 provider id,`provider:模型`
  里的模型那半被丢掉了 —— 于是"同一家两个档"根本走不通(配置看着生效,账单是另一个
  模型)。现在模型一路交到构造实例那一步,缓存键也带上模型(同一家的两个模型是两个
  实例,共享一个会静默串档)。
- 没有任何角色引用槽位时,`applyPresets` 原样返回**同一个 catalog 对象**。"不配
  presets 时行为与之前完全一致"由此是结构上成立的,不靠逐条测试盯着。
- 启动横幅会显示当前队伍(`preset:cheap`):换队之后最该一眼看到的就是"现在用的是哪一队",
  不然只会在账单上发现。
